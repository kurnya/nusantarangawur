# Catatan keputusan

- **F0** Vite 8, TypeScript 6, Vitest 5, ESLint 10 (flat config) — versi terbaru saat setup. Three dikunci `0.128.0` (+ `@types/three@0.128.0`) sesuai brief.
- **F0** `build.assetsDir = 'bundle'` agar JS/CSS hasil build tidak bercampur dengan folder `public/assets/`.
- **F0** `tsconfig` pakai `noUncheckedIndexedAccess` agar akses array aman.
- **F0** Playwright, PeerJS, zod belum dipasang; dipasang saat fase yang memakainya (4/5).
- **F0** Git Bash Windows mengubah nilai env berawalan `/`; gunakan `MSYS_NO_PATHCONV=1` saat uji `VITE_BASE` lokal.
- **F1** Data statis diekstrak dari prototipe oleh `scripts/extract-data.mjs` (menjalankan kode data prototipe apa adanya) ke `src/engine/data/*.json`. Kunci animasi kartu (`fx`) dihitung dari `FXMAP` prototipe dan disimpan di tiap kartu. Jalankan ulang skrip jika prototipe berubah.
- **F1** Satu intent = satu hasil atomik. Mesin tidak menunggu "Terima nasib" (modal): kartu langsung diterapkan dan `CardDrawn` + `BencanaFx` dikirim sebagai events; tampilan yang menahan modal/animasi. Ini perlu agar Host tidak menunggu klik pemain.
- **F1** `owners` berupa array sepanjang 244 petak (bukan objek) supaya hash dan snapshot stabil.
- **F1** Niat: `roll`, `buy`, `build`, `endTurn`, `payJail` (pemain, `pid` ditimpa Host sesuai koneksi) dan `weather`, `endGame` (sistem; Host wajib menolaknya dari client).
- **F1** `roll` juga sah di fase `act` jika `dbl>0` dan tidak di penjara (kembar: lempar lagi). `endTurn` sah di fase `act` walau `dbl>0` (dipakai untuk batas waktu giliran; prototipe menyembunyikan tombolnya).
- **F1** `build` sah di fase `roll` maupun `act` (sama dengan prototipe, bangun lewat klik petak).
- **F1** Cuaca awal dipilih berbobot dari semua 7 jenis. (Prototipe tak sengaja menyingkirkan "Cerah" karena memilih "bukan Cerah" saat mulai.) Pergantian berikutnya tidak pernah sama dengan sebelumnya.
- **F1** Selang waktu cuaca (90 dtk-5 mnt) hanya konstanta + `nextWeatherDelayMs()`; timernya milik Host (fase 4/5), bukan mesin.
- **F1** Mesin menerima 2-8 pemain (tes memakai 2); batas 3-8 untuk lobi ada di `config.ts` (`MIN_PLAYERS`/`MAX_PLAYERS`) dan dipakai lapisan jaringan.
- **F1** Efek kartu `each` (bayar semua pemain) ada di prototipe tapi tidak dipakai kartu mana pun, jadi tidak diportir.
- **F1** Tes Vitest dijalankan lewat PowerShell; di Git Bash Windows vitest sempat gagal dengan `Cannot read properties of undefined (reading 'config')` (penyebab belum diketahui, hanya terjadi di shell itu; `--pool=vmThreads` juga lolos).
- **F2** Kode Three.js prototipe dipecah ke `src/view/` (layout, camera, world, tiles, pawns, ships, sky, fx, models, scene). Urutan pemakaian RNG dekorasi (`makeLcg`, seed 20241116) dipertahankan sama dengan prototipe supaya pulau, pohon, potongan petak, kapal, dan awan identik. Hash derau gunung sengaja memakai perkalian float biasa (bukan `Math.imul`) seperti prototipe.
- **F2** Hanya 12 animasi Bencana yang diportir (banjir, rob, merapi, gempa, tsunami, kebakaran, longsor, kering, puting, meteor, meteorstorm, petir). Efek kartu Nasib di prototipe (nosignal, tilang, kuis, dll.) tidak diportir karena brief menyatakan Nasib tidak perlu animasi besar dan prototipe pun hanya memutarnya untuk Bencana. Varian lombok/krakatau tidak dipakai kartu mana pun.
- **F2** Tidak ada emoji di peta 3D: ikon kota tanpa atlas memakai inisial dalam lingkaran warna provinsi; sprite efek hanya memakai gambar `fx/e*.webp` (jika tidak ada gambarnya, sprite disembunyikan). Gempa memakai `e18` (genteng) sebagai pengganti 🏚️. Emoji kartu tetap tampil di modal HTML.
- **F2** Tampilan menerima event lewat `Presenter` yang menerapkan event ke state tampilan (`src/game/replay.ts`, murni dan dites terhadap mesin), lalu mengganti dengan state akhir dari mesin.
- **F2** Satu animasi besar dibatasi 15 detik (`FX_TIMEOUT_MS`) supaya antrean tidak macet.
- **F2** Bangunan di petak hanya dibangun ulang jika pemilik/level berubah (prototipe membangun ulang seprovinsi; efek tumbuhnya sama).
- **F2** Panel "Uji animasi": tombol cuaca hanya mengganti tampilan (prototipe ikut mengubah aturan). Di mode jaringan cuaca milik Host.
- **F2** UI DOM prototipe (panel saldo + koin terbang, kartu kontrol, catatan per pemain, modal, dadu CSS) ikut diportir sekarang karena dibutuhkan untuk hot-seat setara prototipe; Fase 3 akan menyetel POV/HP.
- **F2** Parameter URL: `?fast=1` (lewati animasi), `?low=1` (kualitas rendah: tanpa bayangan, pohon lebih sedikit, air lebih kasar, hujan lebih sedikit), `?wx=0.01` (percepat timer cuaca untuk uji).
- **F2** Tes browser: Playwright dengan SwiftShader (`playwright.config.ts`). `npm run test:e2e` (fungsional), `npm run test:visual` (tangkapan layar ke `test-results/visual/` untuk diperiksa manual).
- **F3** POV: `Presenter` menerima `me()` (id pemain layar ini; `null` = hot-seat). Kartu pemain sendiri ditandai "kamu"; tombol aksi hanya aktif bila `pov === turn`, selain itu tampil "Menunggu {nama} bermain...".
- **F3** Modal kartu: hot-seat menunggu klik. Di mode jaringan pemilik kartu punya 10 detik, layar lain menutup sendiri setelah 3,5 detik supaya animasi tetap sinkron.
- **F3** Status catatan buka/tutup disimpan per id pemain di `localStorage` (`nn.logOpen.{id}`), dengan cadangan aman bila penyimpanan diblokir.
- **F3** Kamera kembali mengikuti bidak saat giliran berganti (sama dengan `endTurn` prototipe); pemain tetap bebas geser/putar/zoom kapan saja.
- **F3** `prefers-reduced-motion`: tanpa guncangan kamera, kilatan layar dibatasi (aman untuk fotosensitif), koin terbang diganti angka mengambang. Animasi Bencana tetap diputar karena bagian dari isi permainan.
- **F3** HP: toolbar kamera satu baris yang bisa digeser, kotak cuaca di bawah toolbar, petunjuk mouse disembunyikan, kartu pemain lebih ringkas; layar pendek (lanskap) memakai kartu kontrol ringkas.
- **F3** Aksesibilitas: Escape menutup modal (memilih tombol terakhir) dan fokus kembali ke elemen sebelumnya; pergantian giliran diumumkan lewat wilayah `aria-live` tersembunyi.
- **F4** Host bermain lewat client loopback (`linkPair` dalam memori) supaya jalur Host sama dengan pemain lain.
- **F4** Pesan `events` membawa `intent`; client menjalankan mesin deterministik yang sama untuk state lengkap (termasuk RNG, fase, pending) lalu mencocokkan `stateHash`. Pesan tambahan: `welcome`, `profile`, `sync`.
- **F4** Id kursi dinomori ulang 0..n-1 saat mulai (dikirim lewat `welcome` baru) supaya id kursi = id pemain di mesin.
- **F4** Pemain yang keluar dari lobi melepas kursinya; setelah mulai, kursi tetap dan ditandai terputus.
- **F4** Giliran otomatis pemain terputus (45 detik) dan batas waktu giliran (opsi Host) memakai timer yang sama di Host.
- **F4** Transport ketiga `BroadcastChannel` (`?net=tab`) untuk tes Playwright multi-tab yang stabil tanpa internet; PeerJS tetap bawaan dan diuji asap dengan `scripts/peer-smoke.mjs`.
- **F4** Modul online (PeerJS, zod, lobi) dimuat dinamis; bundel utama tetap sekitar 188 kB gzip.
- **F4** `?min=2` hanya untuk uji; aturan resmi minimal 3 pemain.
- **F4** Playwright memakai satu pekerja karena WebGL perangkat lunak berat.
- **F5** Minimal pemain diubah menjadi **2** atas permintaan pemilik (brief awal 3). Berlaku untuk mode satu perangkat dan online (`MIN_PLAYERS` di `config.ts`).
- **F5** Batas waktu giliran berbasis tenggat per giliran ditambah perkiraan lama animasi tiap aksi; Host menyiarkan sisa waktu (`timer`). Waktu habis = giliran otomatis tanpa membeli kota.
- **F5** Kick saat bermain tidak membuat pemain bangkrut (aturan tidak berubah); gilirannya dimainkan otomatis dan tokennya diganti sehingga tidak bisa masuk lagi.
- **F5** Panel diagnosis membaca jalur WebRTC dari `getStats()` (pasangan kandidat terpilih: host, srflx/prflx, atau relay).
- **F5** Keputusan pemilik: **tanpa TURN dulu**, hanya STUN publik. TURN publik bersama (Open Relay) diuji 16-11-2026 dan tidak berfungsi. Dukungan TURN opsional tetap ada dan tidak aktif: `VITE_ICE_SERVERS_URL` (mis. API kredensial Metered, diambil saat bermain, batas 4 detik) atau `VITE_ICE_SERVERS` statis; tombol "Uji TURN", `?relay=1`, dan `scripts/turn-check.mjs` untuk pemeriksaan.
- **F6** Base path ditentukan workflow dari nama repo; repo `USERNAME.github.io` memakai `/`. Build lain memakai `/NAMA-REPO/`.
- **F6** `ci.yml`: job `check` wajib (lint, typecheck, tes, build); job `e2e` Playwright `continue-on-error` dulu karena WebGL perangkat lunak lambat di runner.
- **F6** Variabel opsional `VITE_ICE_SERVERS_URL` ikut diteruskan ke build (kosong = tanpa TURN).
- **F6** `scripts/pages-check.mjs` memeriksa build di sub-path dengan browser sungguhan.
- **P1** (permintaan pemilik setelah rilis) Tombol "Uji animasi" disembunyikan; hanya muncul dengan `?dev=1` (dipakai tes visual).
- **P1** Tampilan cuaca hidup/mati di mode online hanya bisa diubah Host dan berlaku untuk semua layar (`settings.weatherFx`, boleh diubah saat bermain). Ini tetap hanya tampilan; aturan cuaca jalan terus. Di mode satu perangkat tombolnya tetap ada.
- **P1** Kartu Nasib/Bencana dan musibah cuaca: pengambil kartu melihat modal di tengah; pemain lain hanya notifikasi kecil di pojok kanan atas (hilang sendiri 7 detik, bisa diklik). Layar pemain lain menunggu 2 detik supaya animasi sesudahnya tetap kira-kira serempak.
- **P1** Optimasi: label petak hanya digambar ulang jika isinya berubah (sebelumnya 244 kanvas 512 px digambar dan diunggah ke GPU setiap aksi). Profil kualitas Tinggi/Sedang/Rendah + Otomatis (dari jumlah inti CPU, memori, dan jenis perangkat) mengatur resolusi label (512/256 px), bayangan, kepadatan pohon, detail air dan gunung, jumlah hujan, antialias, dan batas FPS (60, atau 30 di Rendah). Mode Otomatis juga menurunkan/menaikkan resolusi render dari FPS terukur. Pilihan ada di menu awal; `?low=1` tetap memaksa Rendah.
- **P2** (permintaan pemilik) Kelola aset kapan saja lewat panel **Aset**: bangun, gadai, tebus, jual ke bank. Boleh di luar giliran (mode online); di mode satu perangkat untuk pemain yang sedang giliran dan setelah animasi selesai.
- **P2** Angka (di `config.ts`): gadai = 60% nilai aset (`MORTGAGE_RATE`); tebus = nilai gadai + 10% (`REDEEM_INTEREST`); jual = nilai aset penuh (sama dengan jual paksa), kota tergadai dipotong biaya tebus. Kota tergadai tidak menarik sewa (lawan yang mendarat bebas sewa) dan tidak bisa dibangun, tapi tetap dihitung untuk kepemilikan provinsi. Jual paksa saat uang negatif mendahulukan kota yang tidak tergadai. Kekayaan akhir memakai nilai jual (sudah dipotong tebus).
- **P2** Kartu Nasib diganti daftar baru dari pemilik (80 buruk, 20 baik) di `scripts/data/nasib.mjs`; Bencana tetap dari prototipe. Peluang Nasib baik per cuaca tidak berubah.
